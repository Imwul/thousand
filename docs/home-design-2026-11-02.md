# 오라클 홈 — 2026-11-02

## 2차 개선 계획

- 비교 A: 고정 바로가기만 크게 강조. 접근은 빠르지만 나머지 30개 상황을 찾는 문제는 남는다.
- 비교 B: 현재 장소별 자동 추천. 탐사 맥락이 종이 기록과 다를 때 필요한 버튼이 이동하므로 이번에는 쓰지 않는다.
- 선택 C: 고정 바로가기 + 검색 가능한 전체 색인. 주요 위치를 유지하고 이름을 몰라도 상황 설명으로 찾게 한다.

색은 기존 바탕 #0b2024, 깊은 면 #07191d, 경계 #335052, 글자 #e8eddf, 탐색 #56dcff, 이어가기 #ff7359을 유지한다. Hahmlet은 홈 제목, SUIT는 조작과 짧은 설명, Barlow Condensed는 게임 제목에만 쓴다. 글씨 크기는 기존 type 토큰을 공유한다.

```
오라클 바로가기 + 동작 안내     | 작업대 이어가기 + 현재 종류/상태
이름·상황 검색                 | 검색 개수 / 전체 표 검색
질문 / 항해 / 시설 / 행성 / 인물 / 전투 / 정거장
질문하기                      | 새 구역 탐사
행성 헥스 탐사                | 적의 이번 행동
스트레스                      | 일반 주사위
최근 사용 (주요 바로가기 중복 제외)
상황별 전체 오라클
질문 그룹                     | 항해 그룹
시설 그룹                     | 행성 그룹
인물 그룹                     | 전투 그룹
정거장
```

모든 큰 영역은 같은 중앙선, 같은 24px 열 간격을 쓴다. 3440에서는 기존 1800px 최대 폭을 유지한다. 13인치 iPad는 동일 너비 두 열, 작은 화면은 전체 목록 한 열·바로가기 두 열을 사용한다. 결과 요약 줄글 대신 이어가기의 종류와 작업 상태만 표시한다. 전체 목록의 영문 부제는 간단한 한국어 용도로 바꾼다. 영문 이름도 검색할 수 있다.

일반 대시보드가 되지 않도록 통계, 장식용 번호, 새 이미지, 자동 추천, 애니메이션은 추가하지 않는다. 주사위는 작은 크기에서도 읽히는 정사각형 외곽과 채운 다섯 눈으로 만든다. 헥스·행동·스트레스 아이콘은 서로 구별한다.

검색은 기존 36개 절차와 보조굴림 이름을 대상으로 한다. 검색창은 타이핑 중 교체하지 않으며 한글 조합과 초점이 유지되어야 한다. 결과 없음, 검색 지우기, 표 검색으로 이어가기, 키보드 진입을 제공한다. 검색/홈 이동으로 굴림이나 기록 생성은 하지 않는다. 작성 중인 폼과 결과 보존은 회귀 검증한다.

### 2차 구현 후 검토

첫 화면 검토에서 검색이 전체 목록 바로 위에 있으면 모바일 스크롤이 길어지는 문제가 보여 홈 상단으로 옮겼다. 검색 중에는 주요/최근 바로가기와 분류 링크를 숨겨 검색 결과가 바로 아래에 나오게 했다. 검색을 지우면 모두 원래 위치로 복원한다. 분류 링크는 실제 앵커로 이동하고 해당 그룹 제목에 키보드 초점이 간다.

‘탄약’ 검색 후 일반 주사위를 열면 기존에 쓰던 다른 보조굴림 옵션이 보이는 불편을 확인했다. 이름이 일치하는 보조굴림을 별도 버튼으로 제공해 정확한 preset과 주사위 식을 함께 열게 했다. 자동 굴림은 하지 않는다. 전체 표 검색으로 넘어갈 때도 검색어를 전달한다.

모바일에서 긴 검색어를 빈 결과 버튼에 반복하면 버튼이 지나치게 길어져, ‘이 검색어로 전체 표 찾기’로 줄였다. 실제 입력값은 그대로 전달한다. 홈뿐 아니라 작업대 굴리기 버튼의 마름모 문자도 공통 주사위 SVG로 바꿨다.

- 전체 테스트 111개 통과. 한글/영문/보조굴림 검색, 한글 조합 중 입력 유지, Enter 초점 이동, Escape/지우기, 검색어 전달, 보조굴림 옵션 설정, 기존 폼/결과/기록 보존을 검증했다.
- 브라우저에서 탄약 검색 → 자동 포탑 옵션 → 주사위 식 작성 → 홈 → 이어가기 흐름을 확인. 기록 수 10개 유지, 입력 `3d6+2` 유지. 확인 후 기존 보조굴림 옵션으로 복원했다.
- 3440px: 모든 주요 영역 중심 x=1720, 두 열 각각 888px. iPad 가로 1376px: 621px씩, 세로 1032px: 465px씩. 분할 704px와 모바일 390px은 목록 한 열, 주요 바로가기 두 열. 홈의 터치 영역 높이 최소 44px, 콘텐츠 가로 넘침 없음.
- 화면 검증은 Chromium 뷰포트 기준이며 실제 iPad Safari 기기 검증은 아니다. 규칙 데이터와 저장 형식 변경 없음.
- 검토 기준: frontend-design 스킬, [Web Interface Guidelines](https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md). 확인한 접근성 항목: 명시적 검색 레이블, 유지되는 live status, 장식 SVG 숨김, 키보드 초점, 최소 터치 영역, 긴 문자열 처리.

## 설계

종이 시트와 저널 옆에서 쓰는 빠른 이동 화면. 게임 제목은 기존 masthead에 유지하고, 홈의 제목은 기능을 설명하는 ‘오라클 바로가기’로 한다.

- 색: 바탕 #0b2024, 깊은 면 #07191d, 보조 면 #112b2e, 글자 #e8eddf, 탐색 #56dcff, 이어가기 #ff7359. 기존 색의 역할을 유지한다.
- 글꼴: SUIT는 탐색과 조작, Hahmlet은 결과의 의미와 본문, Barlow Condensed는 기존 게임 제목. 홈의 주요 버튼은 동일한 크기를 사용한다.
- 구조: 상단 제목과 작업대 이어가기, 자주 쓰는 6개 굴림, 최근 사용, 전체 상황별 목록. 기존 PROCEDURE_GROUPS의 7개 분류와 36개 절차를 사용하여 분류의 의미를 바꾸지 않는다.
- 홈은 최대 1800px로 제한하여 3440 화면에서 버튼이 과하게 늘어나지 않도록 한다. PC와 iPad의 전체 목록은 같은 너비의 2열이며 행 시작선을 맞춘다. 마지막 정거장 묶음은 전체 너비를 사용한다. 800px 이하는 한 열로 바꾸고, 빠른 굴림은 2열을 유지한다.
- 주요 굴림은 질문하기, 새 구역 탐사, 행성 헥스 탐사, 적의 이번 행동, 스트레스, 일반 주사위. 각 버튼은 짧은 기능 설명만 제공한다. 숫자 장식, 일러스트, 감성 문구, 새 색/글꼴은 추가하지 않는다.

같은 크기의 카드만 나열하는 기본 대시보드가 되지 않도록 주요 굴림은 넓은 누름 영역으로, 전체 목록은 조밀한 버튼 목록으로 구분한다. 탐사 도구에서 필요한 정보는 실제 상황명과 이어갈 작업이다. 큰 홍보 문구나 통계가 들어갈 이유가 없다.

## 동작

첫 진입은 홈. 상단 ‘홈’과 게임 제목으로 복귀한다. 홈으로 갈 때 메모와 옵션을 저장하고 현재 작업대의 DOM, 기록, 후속 연결을 보존한다. ‘작업대 이어가기’는 기존 DOM을 다시 보여준다. 홈의 상황 바로가기는 새 굴림의 옵션을 열고 자동 굴림은 하지 않는다.

홈에서는 Cmd/Ctrl+Enter로 숨겨진 굴림이 발생하지 않아야 한다. 표 검색에서 직접 굴리거나 기록을 선택하면 작업대로 전환한다. 캠페인 전환·생성·가져오기 후 홈의 최근 사용과 이어가기를 갱신한다. 새 저장 필드는 필요하지 않다.

구현 후 실제 브라우저에서 홈 → 옵션 → 굴림 → 홈 → 이어가기, 폼 보존, 표 검색 진입, 키보드, 3440·iPad·모바일의 넘침과 정렬을 확인한다.


## 확인 결과

- 렌더러 검증 3개와 기존 컨트롤러 검증을 확장했다. 첫 홈, 자동 굴림 없음, 입력 DOM 보존, 결과 복귀, 표 검색 진입, 캠페인 생성·전환을 검사한다.
- 캠페인 전환 시 마지막 기록만 바꾸고 굴림 종류는 이전 캠페인 것으로 남던 기존 오류를 수정했다. 시작·캠페인 전환·새 캠페인·백업 가져오기가 같은 복원 함수를 사용한다.
- 실제 브라우저에서 홈 → 질문 작성 → 홈 → 이어가기 → 굴림을 확인했다. 모바일에서 일반 주사위로 바로 이동했다.
- 3440px에서는 홈 중심 x=1720과 동일 너비 두 열을 확인했다. iPad 가로 1376px·세로 1032px·모바일 390px에서 가로 넘침이 없으며, 홈의 버튼 높이는 최소 44px이다. 모바일 ‘홈’ 버튼 너비도 44px로 확보한다.
- 기존 결과지, 규칙 데이터, 저장 형식은 변경하지 않는다.
