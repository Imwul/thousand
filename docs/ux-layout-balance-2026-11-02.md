# 결과 화면과 작업대 정렬 · 2026-11-02

사용자 피드백: 가운데 화면이 좌우로 흔들리고 지그재그처럼 보인다. 해당 생물 화면에 한정하지 않고 전체 상황과 보조 화면을 점검한다.

## 적용한 기준

- 텍스트 길이에 따라 칸 하나만 전체 폭으로 보내던 규칙을 제거했다. 일반 값은 행별 두 칸으로 배치하고, 홀수로 남은 칸이나 도해·수치 묶음은 전체 행을 쓴다.
- 같은 행의 제목 띠와 값 영역 높이를 맞춘다. 출처·영문 원문 접기·주사위는 값 아래 한 메타데이터 행에 둔다.
- 생물은 능력치 → 전투·공격 → 공격 조건 → 특성 순으로 읽는다. 전투 수치 네 칸과 공격·피해 두 칸은 넓을 때 한 행의 6칸 기준선에 맞추며, 좁으면 완전한 행으로 나눈다.
- 특성 열과 수치 열을 서로 다른 높이로 독립적으로 쌓던 2026-11-02의 이전 배치를 대체한다.
- 3440px 작업대는 상황 목록과 기록 목록, 옵션과 보조 패널의 폭을 각각 대칭으로 둔다. 결과 영역의 중심이 작업대 중심과 일치한다.
- 상단 제목과 메뉴의 세로 여백을 줄이고, 넓은 화면의 옵션·보조 패널은 낮은 창에서도 내부를 스크롤해 버튼에 접근할 수 있게 한다.
- 1180px 이하에서는 상황 목록을 접고 결과를 전체 폭으로 읽는다. 태블릿의 펼친 상황 목록은 두 열로 배치한다.
- 유물별 감정은 한 표로 모은다. 개별 순번·감정 결과·감정가·실제 굴림을 유지한다.
- 항해·정거장·인물·정산에는 전투 참조를 숨긴다. 저장된 현재 적은 보존하고 전투나 관련 판정에서 다시 보여 준다.
- 빈 보조 패널이 불필요한 간격을 만들지 않게 한다. 기록 목록은 간결한 미리보기로 보이고, 전체 값은 결과 보고서에서 읽는다.
- 설정의 나란한 입력, 백업 버튼, 참조 표의 수치 칸에도 같은 행 정렬 기준을 적용한다.

## 실제 검증

- 로컬 브라우저에서 33개 상황을 모두 선택하고 한 번씩 새로 굴려 결과 행의 빈칸·높이·가로 넘침을 검사했다.
- 일반 생물·혼합 조우·추적 위협·행성·NPC·구역·전투 준비·부상·정산·해킹·항해의 11종을 320, 390, 768, 1024, 1180, 1440, 1920, 2500, 2560, 3440px에서 확인했다. 110개 조합에서 결과 중심 오차, 반쪽 행, 수치/값 칸의 가로 넘침이 없었다.
- 장소 맥락·표 검색·백업·전체 기록 창을 390/1440px에서 확인했다. 태블릿 상황 선택 후 접힘과 모바일 추적 위협 참조도 실제 UI로 확인했다.
- 단위·통합 테스트 74개와 빌드를 통과했다. 저장 결과의 값·주사위 근거 보존 검사도 포함한다.

브라우저 검증은 로컬 테스트 기록으로 진행했다. 사용자가 종이에 기록하며 플레이한 사용성 실험을 실시한 것으로 간주하지 않는다.
